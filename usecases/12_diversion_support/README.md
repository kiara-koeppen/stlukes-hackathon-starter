# Use Case 12 - Diversion Support Reporting Automation

**Requester:** Ashley Schoonover, Diversion Support Team
**Problem archetype:** anomaly detection + narrative report generation

---

## The problem

The Diversion Support Team investigates suspected controlled-substance diversion by clinical staff.
They run **1–6 investigations a month**, and each one costs **3–5 business days** of manual work:
pulling Omnicell dispense logs, Epic medication administration records, pain-score documentation,
and provider orders into Excel, then hand-building pivot tables to compare one nurse or tech against
their peers and spot the anomalies. The data already lives in Databricks - the analyst is doing by
hand what the platform could do in minutes.

**Your job:** automate the analysis. Given a staff member and a date window, benchmark their
dispensing behavior against their peer cohort, apply the team's documented diversion rules, flag the
anomalies, and produce a **structured, human-readable investigation report** with a plain-language
risk narrative - a reviewable draft the investigator validates and owns.

---

## The data (`hackathon.shared.diversion_*`)

Generated by `synthetic_data/generators/gen_12_diversion.py`. Full column dictionary in
`synthetic_data/schemas/12_diversion_schema.md`. **All synthetic and de-identified** - surrogate
keys only, no PHI.

| Table | What it is | Grain |
|---|---|---|
| `diversion_staff` | Staff dimension - `role` (RN/Tech), `unit`. **Cohort = role × unit.** | one row / staff |
| `diversion_omnicell_transactions` | Cabinet events: dispense / waste / return, `amount`, `timestamp`, `witness_id` (nullable) | one row / transaction |
| `diversion_mar` | Epic medication administrations: `admin_amount`, `admin_time`, `order_id` | one row / administration |
| `diversion_pain_scores` | Epic pain documentation: `score` 0–10, `documented_time` | one row / assessment |
| `diversion_provider_orders` | Provider orders: `dose`, `ordering_provider` | one row / order |
| `diversion_iris_scores` | Bluesight ControlCheck (IRIS) per-staff risk score | one row / staff / period |

> The generator **plants a few staff with clear diversion patterns** (`is_planted_diverter = true`)
> against a background of normal behavior, and prints their `staff_id`s when it runs. Use them to
> confirm your detection actually works. That label is synthetic-only - it wouldn't exist in real data.

## Governance guardrails you MUST respect

This is the most governance-sensitive use case in the hackathon: it mixes **PHI** (patient meds,
pain scores) with **HR/legal evidence about employees**. Bake these in from the start - they're part
of the deliverable, not an afterthought:

1. **Synthetic data only.** Never bring real patient or employee data into the sandbox. The whole
   solution is designed to work on synthetic shapes.
2. **Role-based access (RBAC).** In production this report is visible to the **diversion-investigator
   group and no one else**. Design for it: grant to a UC group, use row filters / column masking on
   any PHI, and if you build an app, use **OBO auth** so it runs as the signed-in user (never make
   the app service principal an admin).
3. **Rules and stats decide flags - the AI only narrates.** Do NOT let the LLM decide whether
   someone is diverting. Deterministic rules and cohort z-scores produce the flags; `ai_query` only
   *explains* them. This is what makes the result legally defensible. The narrative must never assert
   guilt or recommend discipline.
4. **Human owns the conclusion.** You're building a triage-and-assembly assistant that produces a
   *draft report for human review*, not an automated accusation. The investigator is the decision-maker.
5. **Audit trail.** Log every AI narrative generation (MLflow tracing) so there's a record of who
   generated what, when, and on what evidence.

---

## Suggested starting point

Build the chain **in order** - this ordering is the whole point of the pattern:

1. **Ingest + join (silver).** Load the six tables and join them the way the analyst does by hand:
   link each Omnicell dispense to its matching MAR administration (patient + staff + med + time
   window), to the governing order, and to nearby pain documentation.
2. **Feature table (gold).** Aggregate to **one row per staff per period** with the behavioral
   features: waste ratio, waste-without-witness %, dispense-without-MAR count, pain-not-dropping %,
   after-hours %, override %, dosage variance, median dispense→admin timing gap.
3. **Rules FIRST (deterministic SQL).** Implement the documented diversion rules as `CASE` logic,
   each emitting a named flag + the evidence rows that triggered it. Start with the two highest-signal,
   lowest-effort ones:
   - **Waste without witness** - `waste` transaction with `witness_id IS NULL`. (Pure `WHERE` clause,
     fastest first win.)
   - **Dispense without administration** - a dispense with no matching MAR row in the window.
   Then add pain-score/med mismatch, timing anomaly, and dosage variance if you have time.
4. **Cohort benchmark (statistics second).** Compute **z-scores** of each feature against the staff
   member's **role × unit cohort**, and blend in the IRIS score as a corroborating signal. This
   quantifies "how far outside normal is this person."
5. **Risk narrative (AI last).** Feed the fired flags + z-scores + evidence into **`ai_query`** with
   a tight prompt: explain in plain language why this pattern is suspicious, cite only the provided
   facts, no conclusion of guilt.
6. **Assemble the report.** Compose flags + cohort comparison + evidence + IRIS + narrative into a
   structured, human-readable report for the top-flagged staff member. Prove it surfaces a *planted*
   persona.

### Hints

- **Rules first, statistics second, AI last.** If you jump straight to the LLM, you've missed the
  point and built something indefensible. The AI's only job is to explain what deterministic logic found.
- **`ai_query` (Foundation Model API)** is the right tool for the narrative - it runs in SQL where the
  data lives, lands in a Delta column, and every call is traceable. No endpoint to manage.
- **Output:** a notebook-rendered report is fine for the MVP. Stretch: a **Databricks App** (with
  RBAC/OBO) and a **generated PDF** (`generate_and_upload_pdf` to a UC Volume) - the format HR/legal
  actually wants. A **Genie Agent** over the gold tables is a nice companion for ad-hoc exploration.
- **Cohort size:** comparing a Tech to an RN produces noise. Keep cohorts to role × unit; for tiny
  units fall back to role-only so you have enough peers for a meaningful z-score.

---

## Scope guidance

**In scope for ~1.5 days:** ingest + join → gold feature table → 2–3 rules → cohort z-scores →
`ai_query` narrative for one flagged staff member → a structured report that correctly surfaces a
planted diverter.

**Out of scope (don't drown):** a polished RBAC app UI, PDF styling, ML-based anomaly detection
(clustering / isolation forest), implementing all five rules, a full MLflow eval harness. Prove the
**chain works end-to-end on one staff member** before polishing any single stage.

**The aha moment:** run the finished chain and watch it single a planted diverter out of the
normal-behavior background - and explain *why* in plain language. That's the demo.
